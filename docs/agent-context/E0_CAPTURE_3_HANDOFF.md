## 2. What capture 3 has to produce

From `roadmap/E0-protocolo-y-enmiendas.md` §1.4.

Pose the agent a task needing **at least two inference hops**, where hop 1's conclusion is a
necessary input to hop 2. Record:

- the output string of hop 1 (the committable conclusion),
- the input string of hop 2 (the premises the LLM chose to carry forward).

Compare **byte for byte**. Repeat with 3–5 distinct tasks. Per link record: literal match yes/no,
and if no, the pair of strings so the kind of rewrite is visible (paraphrase, summary, format
translation, invention).

**It decides:** the nature of `TR-CHAIN-MEDIATED` in the report, and with capture 4, the final
shape of C2's Artefact 2.

### Two things the previous session established that change how you measure

1. **Measure on the raw eval output, not on the LLM-context string.** Between the two there is
   a truncation to `maxFeedback` = 50000 chars that cuts the **head** of the string, mid-token,
   destroying well-formedness. Measured: 108889 → 50000.
2. **Discount the deterministic loop transformations before counting.** `string-safe` replaces
   `\n` → `_newline_`, `""` → `_quote_`, `'` → `_apostrophe_`; `normalize_string` drops invalid
   UTF-8 with `errors="ignore"`. A conclusion containing a newline can never match a fed-back
   premise byte for byte, for reasons that have nothing to do with the mediator. Fail to
   discount these and the faithful ratio comes out artificially low.

Capture 1 gives you a **clean engine baseline**: the same `(|- …)` returns a byte-identical
string across runs and across a container restart. So every difference capture 3 surfaces is
attributable to the mediator and only to it. That is the whole point of having run 1 first.

## 3. The blocker you are inheriting

Everything works under the mock. Under a real LLM provider, **message delivery over the `test`
comm channel never binds.**

| Configuration | Version handshake on the channel | `send_message` |
|---|---|---|
| `-p Test -t test` | `[CommMockServer] Message received: "OmegaClaw version=v0.1.19"` | works |
| `-p Anthropic -t test` | **never arrives** | times out: `Cannot set answer to the mock, error: None` |

The real model *is* answering — the container log shows `(query …)`, `(pin …)`, `(send …)`
turns generated by the model, not by the mock. The API key is valid. Only delivery fails.

Already ruled out: startup order. Tested with `CommMockServer` listening before the container
came up, waiting up to 300 s for the handshake. Same result.

**Unverified hypothesis:** the `test` channel may be coupled to the `Test` provider in
`initChannels`, making *mock channel + real provider* an unsupported combination.

### Suggested order of attack

1. **Read `src/channels.metta` and `initChannels` in `src/loop.metta`** to confirm or kill the
   coupling. Cheapest step, do it first.
2. **If coupled, switch channel rather than provider.** `websocket` against a local server is
   the most direct (`-t websocket` with `WS_URL=ws://172.17.0.1:<port>`); `irc` is what the
   project's own live tests use, but it depends on QuakeNet and rate-limits under load — see
   the persistent-session comments in `Autotests/helpers.py` before choosing it.
3. **Last resort: drive it without a channel.** `docker exec` into the container and invoke the
   metta skill directly, scripting the two hops by hand. This measures the engine but **not**
   what capture 3 is about — what the *LLM* drags forward. If you end up here, say so plainly:
   it is a different experiment, not capture 3.

### Cost control

`maxNewInputLoops: 50` — after each human message the agent keeps looping ~50 turns, one LLM
call each, at `sleepInterval: 1`. With a real provider that burns tokens fast. **Stop the
container as soon as the captures are done**: `docker stop omegaclaw`. Use the cheapest model
the provider supports; the experiment measures the loop, not the model's quality.

## 8. Also pending, cheap, and worth doing

Capture 1 could not construct the case the protocol asks for: **the same conclusion with two
different truth values**, to observe whether `unique-atom` keeps one or both. What is written
in §1 about it is inference from the operator's semantics, explicitly labelled as inference,
not observation.

The operator is:

```metta
(= (|- $a $b)
   (unique-atom (collapse (superpose ((|-nal $a $b) (|-nal $b $a))))))
```

Rules 108–119 of `lib_nal.metta` are the ones to work from. If you find a premise pair where two
rules yield the same conclusion term with different `stv`, run it and record the result. It
firms up the equality predicate of capture 1's decision, which currently rests on reading rather
than on measurement.
