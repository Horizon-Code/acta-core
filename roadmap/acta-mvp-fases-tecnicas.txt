ACTA — MVP técnico (protocolo-first, sidechain-ready)
=================================================

Este documento define las fases técnicas del MVP de ACTA con el objetivo de:
- probar la tesis con máximo rigor técnico
- congelar un core de protocolo verificable
- permitir evolución futura a descentralización, gobernanza y tokenomics
  SIN romper el core (solo mediante módulos)

--------------------------------------------------
PRINCIPIO FUNDAMENTAL
--------------------------------------------------
El core de ACTA define:
- qué es un hecho computacional
- cómo se representa
- cómo se verifica

El core NO define:
- quién gobierna
- quién valida
- cómo se incentiva
- qué token existe

Todo eso se añade después por módulos.

==================================================
FASE 0 — Congelación del protocolo (core intocable)
==================================================
Objetivo:
Definir y congelar el protocolo ACTA v0 como base inmutable.

Tareas:
- Definir ACTAEventV0 (hecho computacional base, schema canónico).
- Definir reglas estrictas de canonicalización.
- Definir hashing determinista.
- Definir ReceiptV0 preparado para múltiples firmas.
- Definir ChronosRefV0 (epoch_id + prev_event_hash) separado del hecho base.
- Definir Epoch + Merkle + proofs.
- Definir BundleV0 (paquete probatorio).

Entregables:
- Especificaciones en docs/spec/
- acta-core (Rust) con tipos y verificación.

==================================================
FASE 1 — acta-core (Rust): verdad verificable
==================================================
Objetivo:
Implementar el núcleo criptográfico y semántico de ACTA.

Tareas:
- Implementar estructuras ACTAEventV0, ReceiptV0, BundleV0.
- Implementar canonicalización determinista.
- Implementar hashing.
- Implementar Chronos (encadenamiento).
- Implementar Merkle tree + proof verification.
- Implementar verificador puro (sin IO, sin red).

Entregable:
- acta-core crate usable desde otros módulos.

==================================================
FASE 2 — Attestation módulo MVP (operador único)
==================================================
Objetivo:
Comprometer hechos de forma inmediata sin consenso.

Tareas:
- Implementar módulo AttestationProvider (interfaz).
- Implementación MVP: single-signer.
- Firma de receipts.
- Verificación de firmas vía acta-core.

Nota:
El diseño admite N firmas sin cambiar el receipt.

Entregable:
- Módulo de atestiguación simple y reemplazable.

==================================================
FASE 3 — Recorder + Chronos (servicio)
==================================================
Objetivo:
Registrar eventos, emitir receipts y garantizar anti-omisión.

Tareas:
- API para registrar eventos.
- Persistencia mínima (DB).
- Emisión inmediata de receipts.
- Enlace con acta-core para hashing/verificación.
- Gestión de epoch en curso.

Entregable:
- Servicio ACTA Recorder funcional.

==================================================
FASE 4 — Epoch builder (cierre off-chain)
==================================================
Objetivo:
Cerrar conjuntos de eventos sin anclaje todavía.

Tareas:
- Agrupar eventos por epoch.
- Construir Merkle tree.
- Calcular epoch_root.
- Generar y almacenar pruebas de inclusión.

Entregable:
- Epochs cerrados con pruebas verificables.

==================================================
FASE 5 — Anchor module (Cardano)
==================================================
Objetivo:
Sellar la historia con fe notarial externa.

Tareas:
- Definir interfaz AnchorBackend.
- Implementación MVP: Cardano anchoring (metadata/datum).
- Publicar epoch_root.
- Obtener tx_id y slot.
- Persistir referencias on-chain.

Nota:
AnchorBackend es intercambiable (sidechain-ready).

Entregable:
- Epochs anclados en Cardano.

==================================================
FASE 6 — Verificador independiente
==================================================
Objetivo:
Permitir verificación sin confiar en ACTA.

Tareas:
- CLI/lib que use acta-core.
- Verificación de:
  - evento
  - receipt(s)
  - Chronos
  - Merkle proof
  - anclaje en Cardano
- Export/import de BundleV0.

Entregable:
- Verificador reproducible por terceros.

==================================================
FASE 7 — Policy reference (obligación previa)
==================================================
Objetivo:
Vincular hechos a obligaciones externas existentes.

Tareas:
- Definir PolicySnapshotV0.
- Repositorio simple de policies versionadas.
- Verificación de vigencia temporal.
- Integración en ACTAEvent.

Nota:
La policy NO se ejecuta.

Entregable:
- Hechos contextualizados jurídicamente.

==================================================
FASE 8 — Demo probatoria (caso ancla)
==================================================
Objetivo:
Demostrar ACTA de principio a fin con un caso real.

Tareas:
- Script generador del caso.
- UI mínima (timeline + detalle).
- Descarga de bundle probatorio.
- Ejecución del verificador.

Entregable:
- Demo técnica defendible ante expertos.

==================================================
FASE 9 — Hardening MVP (sin descentralizar)
==================================================
Objetivo:
Asegurar que el MVP no es un prototipo frágil.

Tareas:
- Gestión básica de claves.
- Observabilidad.
- Dockerización.
- CI mínimo.
- Documentación de verificación.

==================================================
RESULTADO DEL MVP
==================================================
ACTA MVP es:
- un protocolo verificable
- una fe notarial digital computacional
- independiente de gobernanza
- preparado para validadores, stake y sidechain
  SIN reescritura del core
